Make locality legible.

KV Router is a control plane for a simple physical fact: reusing a prefix already resident in an inference cache is cheaper than rebuilding it. This page describes the contracts that make that useful without pretending we know more than the backend can prove.

The thesis

LLM serving is not a stateless HTTP problem. A request carries a prefix; an inference backend may have already paid to build the attention state for part of that prefix. When it has, sending the request there can avoid meaningful prefill work.

The difficult part is not calculating a score. The difficult part is keeping the score honest as requests fail, caches evict, streams run for minutes, and backend health changes. KV Router treats that as systems work.

Design rule

Locality may influence a decision only when its evidence is bounded, scoped, and reversible.

Request path

The hot path is deliberately narrow. The HTTP adapter keeps the original request body and forwarding headers intact. A routing envelope extracts only the metadata needed to make a decision. The selected backend receives an atomic capacity reservation before any upstream call begins.

HTTP ingress → namespace + prefix blocks → cache directory → scheduler reservation → upstream proxy → outcome + telemetry

This separation is intentional: the dashboard reads a bounded event stream, never the live cache data structure. Observation should not turn into a second source of load on the thing being observed.

One bounded directory

Earlier prototypes split the model into a prefix tree and a separate prompt-level LRU. Those structures could disagree: an eviction could disappear from the LRU while remaining routable in the tree. The live router instead uses one bounded directory per backend.

Each entry is scoped by the API contract and model namespace. A successful request touches cumulative prefix keys; the directory retains a fixed number of observed keys and evicts the least recently observed. The result is a conservative prediction, not a claim of universal engine-level cache visibility.

Why bounded matters

Router memory is part of the production threat model. An unfamiliar prompt must not permanently become metadata just because it was large.

Scheduling is a reservation, not a glance.

A queue depth read followed by a later increment lets concurrent requests stampede onto the same apparently idle backend. KV Router reserves capacity atomically before it proxies. The reservation lasts through the full response body or stream, then releases exactly once.

The current policy combines matched prefix blocks with queue pressure and cache occupancy. The policy emits a score that is recorded beside the decision, so an operator can answer “why this backend?” without reconstructing the past from logs.

Outcomes decide residency.

Routing is not proof of a warmed cache. A network failure, rejection, or cancelled request should never make a backend look more local for the next request. The directory commits only after a successful non-streaming response or the first byte of a valid stream.

Health probes use a short, independent client. Inference traffic does not: a five-second whole-body timeout is fine for a probe and wrong for a long generation. Readiness succeeds only when at least one backend has actually passed health checks.

The operator surface

The command center presents a small, production-oriented read model: fleet health, active reservations, bounded directory use, request counts, affinity rate, and recent route decisions. It holds no prompt content and no reversible raw prefix data.

Known limits, stated plainly.

Character-derived prefix hashes are a compatibility fallback—not a substitute for engine-native token blocks. Exact cache identity also depends on tokenizer, model revision, chat template, adapters, multimodal inputs, and serving-engine semantics. The next interface is an engine adapter that supplies those identifiers and, where possible, native residency telemetry.

A local in-memory directory is the right initial topology for one router instance. Multiple routers need explicit ownership or reconciliation; independent replicas must not pretend they share a complete cache view.
